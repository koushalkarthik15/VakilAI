# AI Trust Boundary

This diagram illustrates the trust boundary separating untrusted user data and AI outputs from the deterministic business logic.

```mermaid
flowchart TD
    %% Styling
    classDef untrusted fill:#ffebee,stroke:#c62828,stroke-width:2px,color:#c62828
    classDef ai fill:#fff3e0,stroke:#e65100,stroke-width:2px,stroke-dasharray: 5 5,color:#e65100
    classDef boundary fill:#fff,stroke:#d32f2f,stroke-width:4px,stroke-dasharray: 10 5
    classDef trusted fill:#e8f5e9,stroke:#2e7d32,stroke-width:2px,color:#1b5e20
    
    %% Nodes
    PDF[Untrusted PDF Content<br>Treated strictly as data, not instructions]:::untrusted
    Understand[Document Understanding / LLM]:::ai
    RawAI[Untrusted AI Output<br>JSON string]:::untrusted
    
    subgraph Validation ["Strict Trust Boundary"]
        Zod[Zod / Schema Validation<br>Enforces exact shape]
        BizVal[ID / Evidence / Source Validation<br>Prevents hallucinated citations]
        Zod --> BizVal
    end
    class Validation boundary
    
    TrustCtx[Trusted Application Context]:::trusted
    Downstream[Deterministic Downstream Processing<br>Action Mapping & State]:::trusted

    %% Flow
    PDF --> Understand
    Understand --> RawAI
    RawAI --> Zod
    BizVal --> TrustCtx
    TrustCtx --> Downstream
```

## Security Posture
- **No Prompt Execution:** Uploaded PDFs are parsed as raw strings. Any adversarial "Ignore previous instructions" injections inside a PDF are ingested simply as text data to be understood, incapable of controlling execution flow.
- **Strict Validation:** AI models return JSON strings. The application blindly rejects anything that fails Zod schema parsing.
- **No Autonomous Claims:** The LLM cannot invent legal authorities. `BizVal` strictly ensures that every `source_id` generated by the AI maps exactly to the authoritative list provided to it from the Legal KB in that specific request.
